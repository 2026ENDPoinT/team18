# 한국어 강의 추천 실험 결과

## 범위와 재현

기존 개발용 100개 실행을 재실행해 CSV가 저장된 결과와 바이트 단위로 같음을 확인했다. 기존 코드, 설정, 묶음 manifest와 결과는 `evaluation/baseline/`에 보존했다. 기존 설정은 그대로 두고 별도 실험 데이터·설정·코드 경로를 만들었다. 새 진입 동작은 실험 묶음에만 적용한다. 기존 서비스 로드맵 생성·저장 흐름은 저장소에 아직 없으므로 연결되지 않았다.

정규화, 별칭 위치·긴 일치 우선, 일부 한국어 부정/비교와 A/B 테스트·API 개발·모델 배포 문맥을 처리한다. 복잡한 제외나 선택 고민은 판단하지 못하면 보류한다. 명시적으로 제외한 역량은 의미·직무 신호 합성에도 빠진다. 별도의 서버나 모델 추가 없이 요청당 인코더를 최대 한 번 사용하며, 이수 과목·목록·한영 동일 과목 그룹 조건을 유지한다. 평가 전용 추적은 입력 원문을 저장하지 않는다. 현재 규칙은 한국어 전체를 이해하는 문법 분석기가 아니다.

`prepare_experimental.py`는 원본 태그는 유지하고 실험용 역량 3개(API 설계, 실험 결과 분석, 모델 배포), 웹 별칭과 프론트엔드 직무표 초안을 별도 생성한다. 새로운 역량에 대응하는 과목 태그를 근거 없이 추가하지 않았다. 모두 미검토이고 사전·직무표는 운영용 검토 자료와 구분된다. 원본 41개 역량과 58행의 제목 기반 태그 및 10행 보류도 변하지 않았다.

## 관찰 결과

100개 개발 입력에서 변경 전 `ok` 36 / `no_match` 64, 실험 후 `ok` 44 / `no_match` 56이었다. 34건은 `ok` 유지, 54건은 `no_match` 유지, 10건은 `no_match`에서 `ok`, 2건은 반대였다. 반환 상태 변화는 품질 점수가 아니다. 상세: `before_after.csv`, `experimental_traces.jsonl`. 과목 ID는 CSV의 임시 행 ID다.

- G004: 모바일 앱용 REST API 설계가 기존 모바일 과목 단독 추천에서 API 설계와 백엔드 기초 역량으로 바뀌었다. `api_design`을 직접 연결할 검토된 과목은 없다. API가 백엔드라는 연결 규칙은 모든 문맥에 적합한지 추가 검토가 필요하다.
- G025: A/B 테스트를 소프트웨어 테스트가 아닌 실험 결과 분석·데이터 분석·통계로 다룬다. 실제 강의 적합성은 미검토다.
- G085: 모바일 앱이 아닌 웹사이트라는 요청에서 모바일 과목 대신 웹 과목을 반환한다.
- G088: AI 연구가 아닌 모델 배포는 `model_deployment`를 선택하지만 연결된 과목이 없어 `no_match`로 보류한다. 배포 역량이 학교 과목에 포함되는지는 강의 설명 확인이 필요하다.
- G095: 어느 진로를 선택할지 고민하는 문장은 모호함으로 보류한다. 반면 새 초안 100개 조정용 입력 중 모호 유형 일부는 여전히 `ok`여서 규칙 보완이 필요하다.
- G021: 자연어 데이터 분석 목표는 이전에 `no_match`였으나 데이터 분석 관련 문맥 규칙으로 데이터분석·데이터마이닝·빅데이터처리를 반환한다. 사람이 가정한 데이터 분석·통계 가중치를 직접 주입하면 확률및랜덤변수도 나온다. 어떤 과목이 더 적절한지는 별도 검토가 필요하다.
- G031: 이미지 목표에서 컴퓨터 비전과 AI를 선택하고 컴퓨터비전을 첫 과목으로 추천한다. 넓은 `ai` 태그를 통해 강화학습과 자연어처리도 여전히 추천한다. 가상으로 컴퓨터 비전과 기계학습을 주입하면 컴퓨터비전과 기계학습이 먼저 나온다. 넓은 태그 집중 문제는 남았다.
- G071: 백엔드와 데이터 분석 목표의 자연어 결과는 데이터 분석 비중이 높다. 데이터베이스·데이터 분석을 임의로 같은 비중으로 넣으면 두 과목이 함께 상위에 나온다. 어느 결과가 적절한지는 정답이 없어 판단할 수 없다.
- G074: 이미지 인식 모바일 앱 목표에서 컴퓨터 비전과 모바일 두 역량을 선택하고 두 분야의 과목이 함께 나온다. 다른 복합 목표에서도 작동하는지는 추가 검증이 필요하다.
- G042: 이전에는 보류했으나 실험안은 웹사이트 별칭으로 웹 과목을 반환한다. 보안 목적이 충분히 반영되지 않은 **새 위험 사례**로, 반환 여부의 변화가 개선이라는 뜻은 아니다. G086 비교 목표는 우선 대상이 인식되지 않아 보류하도록 수정했다.

직접 역량 주입의 결과와 역량별 과목 연결 건수·근거 상태, 넓은 태그별 결과, 직무 지정 전후 및 행 순서 안정성은 `diagnostics.json`에 있다. 저장된 태그는 확인된 강의계획서 근거가 아니므로 직접 주입 결과를 정답으로 간주할 수 없다.

임계값 단독 변화는 `ablation_dev.json`에 있다. 예를 들어 직접 역량 임계값을 0.90에서 0.85로 바꾸면 개발 100건의 결과 목록이 50건 달라지고 `ok`는 44에서 74로 늘었다. 사람의 관련도·제외 라벨이 없으므로 오추천과 적합도를 비교할 수 없고 이 값을 승격하지 않았다. 직무 임계값과 과목 점수 기준을 각각 바꾼 결과도 기록했다. 역량별 복수 대표 설명, 설명 확장, 넓은 태그 제한, 복합 목표 혼합 비율의 개별 통제 실험은 아직 하지 않았다.

## 평가 자료와 테스트

`draft_200.csv`는 새 목표 후보 200개(조정 100 / 최종 점검 후보 100)다. 50개 의미 그룹당 표현 4개를 같은 분할에 두었다. 생성 문장과 역량·보류 가설은 모두 `draft`이며 문법과 의미 그룹의 중복·누출까지 사람이 재검토해야 한다. 기존 100개를 사전 작성에 참고했으므로 독립 성능 주장에 사용할 수 없고, 자동 생성 최종 후보도 독립성·대표성을 아직 입증하지 못했다. 최종 점검 후보는 설정 조정에 사용하지 않았다.

`evaluate.py`는 의미 방식, 과목명 일치, 별칭 기반 방식의 결과 건수를 같은 목록·동일 과목 처리 조건에서 비교한다. `review_status=reviewed`만 지표에 포함하고, 관련도 JSON이 없으면 과목 관련도와 nDCG는 계산하지 않는다. 현재 조정 후보 100건은 전부 초안이라 역량 정밀도·재현율, 과목 적합률·nDCG, 제외 위반율, 범위 밖 오추천률 등은 계산 불가다. `draft_adjustment_metrics.json`의 상태 건수는 오직 실행 현황이다. 별칭 기준선은 모델이 아니며 과목명 기준선은 정확한 과목명 일치를 사용한다.

검토자는 우선 문장 의미, 허용 역량 ID와 제외 범위, 추천/보류, 과목별 관련도(0~3), 근거를 개별 검토하고 `review_status`를 `reviewed`로 변경한다. 한영 과목은 대표 ID를 사용한다. 불확실한 라벨은 보류하고, 같은 의미의 예문을 다른 분할에 넣지 않는다. 의미 그룹을 서로 비교해 겹침을 없애고 최종 점검은 설정 확정 후에만 시행해야 한다. 표본은 자동 생성 문장에 편중되어 있어 실제 사용자 문장을 동의와 비식별 처리 후 별도 확보하는 것이 필요하다.

테스트 21개가 통과했다(그중 6개는 실제 E5 묶음을 사용하는 통합 회귀 검사다). 30개 제외 표현 최소대립쌍(각각 양방향)과 비교·복합·문맥, 스냅샷 고정, 이수·한영 그룹, 사용자별 결과, 후보 없음·모델 오류 구분을 포함한다. 구현에는 공유 결과 캐시가 없다. 하나의 테스트 스냅샷에만 통과한 것이 실제 품질이나 전체 부정 해석의 보장은 아니다.

## 로컬 모델·자원 측정

상세값과 해시, 토큰 길이, 패키지·환경·동시성별 대기/추론/전체 p50·p95는 `evaluation/benchmarks/local_fp32.json`, `local_int8.json`에 있다. Apple M4, macOS ARM64, Python 3.12, 물리 메모리 16 GiB, CPU/RAM 제한 미설정, 세션 1개·스레드 1개·캐시 없음, 길이별 반복 10회와 동시성 1·2·4·8에서 측정했다. 모델 다운로드 시간은 포함하지 않는다. 프로세스 생성~준비는 별도 자식 프로세스로 측정했고, RSS는 운영 목표 서버의 메모리 요구량이 아니다. 외부 부하 통제 없이 실행했고 p95 표본도 작다.

| 측정 | FP32 | INT8 |
|---|---:|---:|
| ONNX 파일 | 약 448.5 MiB | 약 112.7 MiB |
| 시작~준비 | 약 613 ms | 약 402 ms |
| 로드 후 RSS | 약 1,655 MiB | 약 734 MiB |
| 최대 RSS | 약 1,658 MiB | 약 741 MiB |
| warm 23토큰 p50 / p95 | 약 11.9 / 12.0 ms | 약 8.3 / 8.4 ms |
| 동시 8개 요청 전체 p95 | 약 92.2 ms | 약 62.3 ms |

요청별 추론은 같은 프로세스 안의 잠금으로 직렬화되며 벤치마크는 측정용 외부 잠금에서 큐 대기를 구분했다. 타임아웃은 설정하지 않았고 목표 운영 환경은 미측정이다. 해시 계산 시 전체 파일을 읽는 구현이 RSS/최대 RSS를 높일 가능성은 별도 분석이 필요하다.

INT8은 FP32와 각각 해당 인코더로 별도 생성한 사전 벡터를 사용했다. 개발 입력 100건에서 INT8과 FP32의 추천 목록·순서가 2건 달랐고 상태는 1건 달랐다. 규칙이 감지한 제외 역량이 결과 역량에 다시 들어간 건수는 양쪽 모두 0건이었지만, 이는 사람이 확인한 전체 제외 위반률이 아니다. `fp32_int8_comparison.json`을 참고한다. 검토된 관련도 라벨이 없어 품질 손실을 계산하거나 INT8을 운영용으로 선택하지 않았다. 비교 전에 작성한 허용 손실 초안은 `config/quantization-evaluation.json`이며 목표 자원과 기준은 아직 미합의다. 더 큰 E5-base는 품질·비용 비교 근거가 부족해 측정하지 않았다.
