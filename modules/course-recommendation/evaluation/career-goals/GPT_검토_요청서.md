# 경량 강의 추천 모델 및 시험 결과 검토 요청

> 과거 검토 요청 문서다. 당시 수치와 묶음은 과거 실행에 대한 설명이며 현재 결과는 `runs/20261108T054152Z-db17025d/`를 참조한다.

아래는 현재 구현과 시험 결과입니다. **구조와 결과를 검토하고, 잘못된 추천을 줄이면서 한국어 진로 표현을 더 잘 처리할 수 있는 구체적인 보완 방안을 제안해 주세요.** 관찰된 사실, 가능한 원인, 검증이 필요한 가설을 구분해 주세요. 모델 교체가 필요하다면 현재 방식 개선과의 비용·품질 trade-off도 비교해 주세요.

## 1. 만들려는 기능과 제약

대학생이 입력한 희망 진로와 선택 직무를 바탕으로, 현재 선택한 학과 과목 목록에서 관련 강의를 최대 5개 추천합니다. 이수했다고 선택한 과목은 제외합니다. 특정 과목을 현재 수강할 수 있는지, 졸업요건을 충족하는지 또는 사용자가 해당 역량을 보유했는지 판단하는 기능은 아닙니다.

초기 설계는 가벼운 CPU 실행을 목표로 합니다. 별도 추천 서버, LLM 서버, 벡터 DB, 추천 이유 생성, 운영 중 과목 재분석은 도입하지 않습니다. 과목별 역량 태그와 직무별 역량표, 역량·직무 임베딩은 사전에 준비하고, 실행 시 진로 입력을 한 번 임베딩해 점수를 계산합니다. CPU·RAM의 확정 제약과 운영 목표 지연 시간은 아직 없습니다. 제안할 때 불필요하게 복잡한 구성을 전제로 하지 말아 주세요.

## 2. 현재 구현

- 인코더: `intfloat/multilingual-e5-small`, revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`, FP32 ONNX, 384차원. query와 passage 접두어, attention-mask 평균 풀링과 L2 정규화를 사용합니다. 256토큰을 초과하면 입력 오류로 반환합니다.
- 원본 모델과 ONNX의 토큰 ID 및 임베딩을 세 문장에서 비교했습니다. 토큰 ID는 같았고 임베딩 코사인 유사도는 세 문장 모두 0.999999 이상이었습니다. 이는 모델 변환 동작 확인이지 추천 품질 평가가 아닙니다. 양자화 모델 비교나 서버 부하 측정은 하지 않았습니다.
- 진로와 선택 직무를 하나의 query로 인코딩하고, 역량 설명 및 대표 직무 설명과 코사인 유사도를 계산합니다. 직무가 명시적으로 선택되면 해당 직무표를 사용하고, 그렇지 않으면 별칭 또는 직무 유사도와 상위 후보 간 차이 조건을 사용합니다.
- 역량의 명시적 별칭을 찾고 간단한 부정 패턴을 확인합니다. 직접 관련 역량은 유사도 임계값을 넘은 후보와 긍정 별칭을 합쳐 최대 8개를 선택하고 역순위 `1/rank`를 정규화합니다. 직무표 우선순위도 정규화합니다. 두 신호가 있으면 직접 신호 0.6, 직무표 0.4로 합치고 상위 8개를 정규화합니다. 하나만 있으면 그 신호를 사용합니다.
- 과목 점수는 `Σ(역량 우선순위 × 과목 태그 coverage)`입니다. 양수이면서 최소 점수 이상인 과목만 최대 5개 반환합니다. 적합한 과목이 없으면 `no_match`, 자료나 모델 등을 사용할 수 없으면 `unavailable`입니다.
- 과목목록 ID와 목록 버전을 스냅샷 및 정적 묶음과 비교하고 이수 선택을 제외합니다. 한국어·영어 수업으로 나뉘는 동일 과목은 명시적 그룹으로 묶어 추천에 한 번만 표시하고, 어느 한쪽을 이수해도 그룹 전체를 제외합니다. 기본 표시 순서는 한국어 행 우선입니다.
- 임시 설정: 역량 유사도 임계값 `0.9`, 직무 유사도 임계값 `0.9`, 직무 후보 간 최소 차이 `0.05`, 과목 최소 점수 `0.01`. **표본으로 최적화하거나 검증한 값이 아닙니다.** 유사도나 과목 점수는 확률이 아닙니다.

## 3. 과목 및 태그 데이터

사용자가 제공한 서울과기대 컴퓨터공학과 2026 전공과목 가공 CSV를 사용했습니다. CSV는 68행이며 학년, 학기, 이수구분, 과목명, 학점, 이론·실습 정보가 있습니다. **강의 설명과 실제 과목 ID는 없습니다.** `csv-row-001` 같은 ID는 이 CSV에만 유효한 임시 행 ID입니다. 한영 수업 16개 쌍은 사용자가 같은 내용을 배우는 수업이라고 확인한 관계를 반영했습니다.

시험 묶음 `seoultech-test-v4`에는 역량 41개, 대표 직무 4개(백엔드 개발자, 데이터 분석가, 머신러닝 엔지니어, 보안 엔지니어)가 있습니다. 직무별 우선순위는 임시 가설입니다. 과목명만으로 추정해 58개 행에 태그를 붙였고, 나머지 10개는 내용이 모호해 보류했습니다. 58개 행의 태그 수는 1개 23행, 2개 26행, 3개 8행, 4개 1행입니다. 제목 중심 태그에 `coverage=1.0`, 추가 관련 가능성에 `0.5`를 부여했습니다. **모든 태그와 coverage는 미검토 추정이며 실제 강의 내용이나 학습 비중을 확인한 값이 아닙니다.** 예를 들어 데이터베이스 제목만으로 SQL을 다룬다고 확정하지 않아 SQL 태그를 붙이지 않았습니다.

과목 태그는 이번 CSV에 대해 사람이 제목을 보고 스크립트에 직접 작성한 것입니다. 새로운 과목명을 입력받아 자동으로 태그를 생성하는 기능은 없습니다. 100개 진로 예시를 참고해 역량 사전을 확장했으므로, 이 100개를 독립적인 최종 평가셋으로 사용할 수 없습니다.

## 4. 100개 목표 실행 방법과 관찰 결과

한국어 진로 문장 100개를 각 10개씩 다음 유형으로 구성했습니다: 백엔드·서버, 프론트엔드·모바일, 데이터 분석, 머신러닝·AI, 보안·네트워크, 시스템·임베디드, 소프트웨어·게임, 복합 진로, 부정·제외, 모호·범위 밖. 각 목표의 관련 역량은 일반적 가설로 수동 작성했으며 검토된 정답이 아닙니다. 모호·범위 밖 10개는 역량 확정을 보류했습니다.

100개 모두 목표 문장만 입력했습니다. 별도 `target_role` 선택은 없고, 이수 선택은 빈 목록이며 선택 확인 상태는 `unconfirmed`입니다. 이 상태를 공식 미이수로 해석하면 안 됩니다. 100개 모두 동일한 과목 목록과 묶음을 사용했습니다. 모델 실행과 점수 계산 결과는 다음과 같습니다.

| 백엔드·서버 | 3 | 7 |
| 프론트엔드·모바일 | 1 | 9 |
| 데이터 분석 | 2 | 8 |

**이 수치는 결과 반환 건수이지 정확도·재현율·추천 적합률이 아닙니다.** `no_match`가 항상 실패는 아니고 `ok`가 적절한 추천을 뜻하지도 않습니다. 사람의 정답 및 기준 과목 라벨이 없으므로 태그 정밀도, 상위 5개 적합도, 키워드 검색 대비 성능은 아직 측정하지 않았습니다. 입력별 전체 결과와 가설 역량은 별도 CSV를 참고해 주세요.

### 확인된 사례

1. `G021`: “사용자 행동 데이터를 분석해 서비스 개선에 기여하고 싶어요” → `no_match`, 선택된 역량 없음. 데이터 분석과 관련될 수 있는 구체적 목표인데 후보가 생성되지 않았습니다. 임계값·표현·사전 등의 영향은 별도 확인이 필요합니다.

5. `G085`: “모바일 앱이 아닌 웹사이트를 만들고 싶어요” → **모바일 프로그래밍 역량만 선택하고 모바일프로그래밍을 추천했습니다.** 사용자의 명시적 제외 의도와 반대되는 오류 사례입니다. 현재 부정 규칙이 별칭 바로 뒤에 오는 일부 패턴에 의존해 조사와 문장 구조를 충분히 처리하지 못했을 가능성이 있습니다.
6. `G095`: “프로그래밍을 할지 보안을 할지 아직 고민 중이에요” → 두 역량과 과목을 추천했습니다. 진로 선택이 모호한 경우 추천 보류 또는 추가 질문이 나은지 검토가 필요합니다.

## 5. 평가자에게 요청할 검토

1. 위 결과를 바탕으로 **가장 먼저 고칠 문제를 우선순위별로** 제시해 주세요. 각 문제에 관찰 근거, 가능한 원인, 최소 수정안, 예상되는 부작용, 확인할 테스트를 적어 주세요. G085처럼 사용자의 제외 의도를 거스르는 사례를 특히 검토해 주세요.
2. 한국어 조사·띄어쓰기·부정·비교·복합 목표·모호한 목표를 현재 소형 인코더와 제한된 규칙으로 처리하는 현실적인 방법을 제안해 주세요. 단순히 임계값을 낮추는 개선안은 범위 밖 목표의 오추천 가능성과 함께 검토해 주세요.
3. 역량 사전의 너무 넓은 태그와 미포함 역량, 이름만으로 추정한 과목 태그, 직무표의 불완전성이 각각 결과에 미치는 영향을 분리해 진단하는 방법을 제안해 주세요. 없는 강의계획서 내용을 사실처럼 만들어 보완하지 말아 주세요.
4. 과목 추천을 실제로 평가할 수 있도록 사람의 역량·과목 정답 작성 절차, 복수 정답과 판단 보류, 조정용·최종 점검용 분리, 직무별/부정/범위 밖 목표별 지표, 키워드 검색 기준선, 적절한 표본 크기 및 한계를 제안해 주세요. 이 100개는 사전 작성에 참고했으므로 별도 검증셋이 필요합니다.
5. 모델 원본과 양자화 후보의 추천 변화 및 운영 환경의 cold start, 첫 요청, warm p50/p95, 동시 요청 대기, 최대 RSS를 재현 가능하게 측정하는 계획을 제안해 주세요. 측정하지 않은 성능을 추정치로 확정하지 말아 주세요.
6. **바로 실행할 수 있는 실험 3~5개**를 입력 예시, 비교 대상, 성공 기준, 필요한 데이터, 우선순위와 함께 제안해 주세요. 이미 확인된 사실과 추가 측정이 필요한 가설을 구분해 주세요.
