# Non-AI MVP 진행 상태

## P3 완료 범위

- `pypdf 5.9.0`, `python-docx 1.2.0`으로 PDF·DOCX를 파싱하고 UTF-8 TXT를 검증·추출한다. AI 호출과 OCR은 없다. 텍스트와 페이지·문단·문자 범위를 저장하고 확인된 이미지·미추출 범위는 partial 또는 needs_ocr로 구분한다. 읽을 본문이 없으면 failed로 처리한다.
- A11~A16 문서 업로드·목록·삭제·버전 조회·부분 확인·재추출 API와 `004_p3_documents.sql`의 `project_documents`, `document_extractions`를 구현했다. 세션 소유권과 입력 버전을 검증하고 재추출 이력을 보존한다.
- 서버가 발급한 키로 비공개 로컬 저장소에 원본을 보관하고 DB에는 메타데이터와 추출 이력을 둔다. 삭제 시 현재 입력에서 즉시 제외하며 워커가 원본과 추출 자료를 정리한다. 정리 실패는 재시도하고 만료된 작업 lease를 회수한다.
- 기본 제한은 문서당 10MiB, 계획당 10개, PDF 100페이지, DOCX 압축 해제 30MiB·1,000개 항목, 추출 텍스트 100만 문자다. 허용 형식과 파일 크기·개수는 서버가 검사한다.
- 실제 DOCX·PDF·TXT 업로드, 파싱·부분 확인·OCR 필요·실패, 중단 후 재개, 중복 실행 방지, 세션 분리, 재추출 버전, 삭제 실패·재시도, 10MiB 프록시 업로드를 검증했다. 백엔드 통합 테스트 10개 및 웹 빌드·정적 검사 통과. Brave 헤드리스로 업로드·확인·다음 단계 제한·새로고침·삭제를 확인했다.
- 문서 업로드, 삭제, 추출 완료 및 부분 확인은 입력 버전을 갱신한다. 문서가 ready이거나 현재 partial 버전의 확인이 있을 때만 다음 이동 버튼이 활성화된다.
- 경험·역량 해석, AI 분석 및 로드맵 생성은 구현하지 않았다. 실제 클라우드 저장소·배포는 별도 작업이다.


## P2 완료 범위

- SQLite 마이그레이션 `002_p2_courses.sql`, `003_catalog_university_guard.sql`로 과목, 목록별 표시 정보 및 요청별 이수 선택과 학교 관계 검증을 추가했다. 기존 학교·학과·목록 및 계획 테이블을 재사용한다.
- A05~A10: `GET /api/universities`, `GET /api/universities/{id}/departments`, `GET /api/departments/{id}/catalogs`, `GET /api/roadmap-inputs/{id}/courses`, `PATCH /api/roadmap-inputs/{id}/course-selections`, `POST /api/roadmap-inputs/{id}/course-selection-review`를 구현했다. 목록 ID와 버전 검사, 소유권 확인, 토글 저장과 확인 해제·버전 갱신은 트랜잭션으로 처리한다.
- 검색·학년·전공 구분·선택 과목 필터, 페이지 이동, 선택 요약, 목록 밖 기존 선택, 저장 상태, 0개 확인과 누락 신고를 제공한다. 선택 요청은 직렬 처리하며 실패·충돌 시 재조회하기 전 확인을 막는다.
- `python3 apps/api/app/scripts/seed_dev.py`로 가상 학교 1개·가상 학과 1개·가상 목록 2개와 가상 과목 7개를 명시적으로 적재할 수 있다. 출처는 팀18이 직접 만든 개발용 예시이며 공식 교육과정이 아니다. 목록 간 동일 과목 ID와 이름만 같은 다른 ID를 포함한다. 적재는 여러 번 실행해도 중복되지 않는다.
- 검증: `npm run build`, `npm run check`, Python 컴파일, HTTP 통합 테스트 6개 통과. 테스트는 소유권, 0개·부분 확인, 유효하지 않은 값과 중복, 검색·요약, 목록 변경, 동명 과목 구분, 일괄 저장 원자성과 동시 요청 충돌을 확인한다. Brave 헤드리스에서 기본 정보 선택, 0개 확인, 토글 저장·새로고침, 필터, 누락 신고와 목록 변경 후 이전 선택 보존을 확인했다.
- 이 항목은 P2 당시 기록이며 문서 업로드는 위 P3 범위에서 구현했다. AI 분석, 추천·결과 생성은 구현하지 않았다. 실제 학교 자료 도입은 출처 확보 및 별도 적재가 필요하다.


## P1 완료 범위

- 서버가 익명 세션을 발급하고 토큰의 SHA-256 해시와 만료 시각을 저장한다. 쿠키는 HttpOnly·SameSite=Strict이며 Secure가 기본값이다. 로컬 HTTP에서만 명시적으로 Secure를 끌 수 있다. 쓰기 요청은 허용 Origin도 검사한다.
- `POST /api/roadmap-inputs`, `GET /api/roadmap-inputs/resume`, `GET /api/roadmap-inputs/{request_id}`, `PATCH /api/roadmap-inputs/{request_id}`를 구현했다. 브라우저는 Next.js의 `/api` 프록시를 사용한다. `GET /api/reference`는 선택 가능한 학교·학과·목록 기준 자료를 제공한다.
- 계획 생성·이어 쓰기와 기본 정보 저장·복원을 DB와 연결했다. 데이터 접근마다 세션 소유자를 확인하고, 잘못된 입력은 422, 오래된 입력 버전은 409로 처리한다. 실제 변경이 있을 때만 전체 버전을 올리고, 학교·학과·목록 변경 시 선택 버전 증가와 확인 해제를 함께 수행한다.
- 최초 마이그레이션 `apps/api/migrations/001_p1.sql`은 `session_owners`, `roadmap_inputs`, `universities`, `departments`, `course_catalogs`를 만든다. SQLite 어댑터와 실행 환경 설정은 분리했다. 실제 기준 데이터는 제공되지 않아 목록이 비어 있다.
- 사용자 입력, 저장 중·완료·실패·충돌 상태는 API 응답을 반영한다. 저장되지 않은 변경은 별도로 안내한다.

## P0 및 확인한 자료

6개 화면과 결과 5탭, 공통 화면 구성 및 API 호출 기반을 유지했다. README, 폴더 구조 문서, 최신 시스템 맵, 학생 입력 데이터 명세 ver.3, 기존 코드와 P0 진행 기록을 확인했다. 저장소와 상위 경로에서 AGENTS.md는 찾지 못했다.

## 검증

- `npm run build`, `npm run check`, Python 컴파일 확인.
- HTTP 통합 테스트: 세션별 조회·수정 차단, Origin 검증, 입력·관계 오류, NULL과 0, 변경 없는 저장, 충돌과 동시 수정, DB 재열기 확인.
- Brave 헤드리스: 계획 없음, 생성·저장, 새로고침 복원, 이어 쓰기 및 쿠키 속성 확인.
- 별도 API 프로세스를 종료하고 같은 SQLite 파일로 재시작한 후 저장된 계획과 버전 복원 확인.

## P1 시점의 P2 인계 기록

`course_catalogs`, 계획의 목록 ID, 선택 버전 및 확인 필드는 향후 과목 목록·이수 토글을 위한 확장 지점이다. 과목 테이블과 토글 저장·확인 API는 위의 P2 완료 범위에 반영했다. 실제 기준 데이터 수집은 미구현이다. 이 문장은 P1 당시 기록이다. 문서 업로드·파일 저장은 위 P3 범위에서 구현했다. 계정·로그인, AI 분석, 결과 생성과 추천은 미구현이다. 30일 세션 만료나 쿠키 삭제 후 계정 기반 복구는 제공하지 않는다.

현재 SQLite와 표준 라이브러리 HTTP 서버는 로컬 환경을 위한 구현이다. 클라우드 DB·파일 저장소를 사용할 때는 어댑터와 해당 DB 마이그레이션 및 운영 구성이 별도로 필요하며 실제 배포는 수행하지 않았다. API 주소·DB 경로·파일 저장소 예약 경로·Origin·쿠키 및 실행 설정은 환경변수로 분리했다. P1은 별도 비밀키 없이 무작위 세션 토큰을 발급한다.
