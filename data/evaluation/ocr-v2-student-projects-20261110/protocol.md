# 추론 전 고정 프로토콜

대상: 2026ENDPoinT/team18의 ocr_test 현재 HEAD. 실행 당시 전체 커밋과 코드/모델 파일 SHA-256을 환경 기록에 저장한다. 과거 46e777e를 강제하지 않는다. 원 평가 폴더는 읽기 전용으로 다루고 파일별 해시를 전후 검증한다.

## 표본과 입력

- 독립 프로젝트 12개, 평가 페이지 36장. 프로젝트별 소개서 1쪽과 슬라이드 2쪽으로, 36개의 독립 프로젝트가 아니다. 동일 프로젝트 페이지 사이 사실이 반복되므로 페이지/사실 관측을 독립 표본으로 해석하지 않는다.
- 소개서 본문형 6, 소제목·불릿형 6. 슬라이드 제목·불릿 8, 좌우 비교 8, 화면·그래프 결과 8. 프로젝트 01–04는 불릿+비교, 05–08은 불릿+결과, 09–12는 비교+결과이다. 형식 비교는 무작위 배정 효과 추정이 아니라 기술 통계이며 내용·글꼴·밀도가 함께 다르다.
- 전부 새 가상 대학생 프로젝트. 실제 학생·실적에 대한 주장이 아니다. 학습 데이터와의 정확한 비중복은 입증하지 못한다. 기존 합성 원문을 복제하지 않았다.
- 소개서 1240×1754, 슬라이드 1600×900. PNG에 고정 텍스트를 직접 렌더링하며 PDF/문서 텍스트 레이어를 만들지 않는다. 그래프는 고정 수치로 그린다. 화면 예시는 합성 UI 래스터로 실제 서비스 캡처가 아니다. 도식의 미표기 값·막대 좌표는 정답에 추가하지 않는다. 축소/흐림 변형 없음. QA 연락판은 평가 입력이 아니다.
- Nanum Gothic / Nanum Myeongjo 두 글꼴, 색상과 본문·라벨형 구성 변형. 소개서 본문 29–31px, 슬라이드 주요 본문 29–38px, 슬라이드 제목 53–56px; 작은 글자는 캡션/메타정보만 사용. 로컬 PPTX artifact runtime 미제공이므로 평가 PNG를 직접 렌더링한다.
- prepare.py의 글리프 커버리지, 글자 경계, 글자 간 겹침 검사와 렌더링 시각 검수를 수행한다. 검수 완료 후 이미지, 전체 정답, 읽기 순서, 핵심 사실, 생성 원문, 채점 규칙·스크립트의 해시를 manifest에 고정한다. 추론 이후 수정/제외/재렌더링 금지.

## 정답과 읽기 순서

- 화면에 보이는 제목, 글머리표, 본문, 숫자, 그래프 라벨, 캡션, 꼬리말을 모두 포함한다. 실제 줄마다 LF 1개, 마지막 LF는 없다. 타이포그래피 색상·선·도형은 문자로 전사하지 않는다.
- 소개서·불릿 슬라이드: 위→아래, 라벨→해당 내용. 좌우 비교: 상단 공통 제목/기술 → 왼쪽 제목 → 왼쪽 본문 전체 → 오른쪽 제목 → 오른쪽 본문 전체 → 꼬리말.
- 결과 페이지: 공통 제목 → 왼쪽 증거 영역(제목→개선 전 라벨·값→개선 후 라벨·값→캡션) → 오른쪽 설명 위→아래 → 꼬리말. 읽기 순서 JSON에 실제 줄과 사각형 좌표를 별도 보존한다.
- key_facts는 페이지에 표시된 주요 선언 기여 2개(팀/본인), 기술명별 1개, 주요 성과 전후 관계 1개를 정의한다. 부수 설명의 모든 활동을 개별 사실로 세지는 않는다. 비교 슬라이드에는 성과 사실을 만들지 않고, 결과 슬라이드에는 기술·역할 사실을 만들지 않는다. 반복된 같은 사실은 페이지 내 1회 평가한다.

## 실행

- 실제 ai/local/ocr.py의 LocalOCR('local')를 수정 없이 호출. 서비스 기본 orientation=auto, layout=rows, crop_padding=0. 호출 입력은 오직 extract('png', PNG bytes). 생성 원문/정답/사실은 모델에 전달하지 않는다. 원문을 읽는 채점은 추론 종료 후 수행한다.
- Hugging Face offline 설정, 로컬 검출기와 ocr-v2만 사용. Gemini, 외부 LLM/API, OCR 후처리, 튜닝 없음. 반환 문자열을 그대로 UTF-8 저장한다. LocalOCR 내부의 기존 정렬/strip/join은 서비스 자체 동작이다.
- 과거 평가와 동일하게 torch CPU thread=2, interop=1. 장치는 서비스의 CUDA 여부 판단 그대로. 별도 준비 이미지 1회. import, 초기화, 준비 시간을 장당 추론 시간에서 제외한다. 입력별 1회, PNG bytes 메모리 준비 후부터 extract 반환까지 측정한다. 운영 처리량 또는 반복 측정 분산은 아니다.
- 모든 36장을 실행한다. 비어 있지 않은 반환은 success, 빈 문자열은 empty, 예외는 error. 오류는 traceback 보존하고 빈 예측으로 전체 CER/사실 분모에 포함한다. 성공 여부는 OCR 정확도를 뜻하지 않는다.

## CER

기존 evaluate.py의 NFC와 Levenshtein 단위 비용 및 editops 집계를 재사용한다. 공백 포함 CER은 LF·공백을 포함하고, 공백 제거 CER은 str.isspace() 문자만 제거한다. 대소문자·기호·숫자를 교정하지 않는다. 각 집계는 총 편집거리 / 총 정답 문자 수이며 페이지 CER 단순 평균이 아니다. 전체·소개서·슬라이드·5개 세부 레이아웃·프로젝트별 점수를 저장한다. 독립 표준 라이브러리 DP로 저장 정답/예측에서 전부 재계산한다.

## 핵심 사실 채점 (score_facts.py, 외부 LLM 없음)

A. 기술명: 토큰 경계를 포함한 정확 대소문자·기호. 여러 단어 사이 줄바꿈/공백은 허용하지만 기술명 내부 문자/기호를 합치거나 보정하지 않는다. C++→C, C#→C, Next.js→Nextjs는 실패. 페이지 내 한 번 정확히 남으면 보존으로 센다. 전체 등장 횟수 검사가 아니다.

B. 역할 귀속: 사실의 핵심 작업 구절(접속 조사로 연결된 경우 작업 앵커들)을 국소적으로 복원하고, 같은 문장의 가장 가까운 명시적 주어 또는 단일 열 제목 범위를 판정한다. 주어만 있거나 키워드만 남으면 성공하지 않는다. 두 열 제목이 모두 작업보다 먼저 나열되고 작업이 뒤섞인 경우, 이미지의 열 좌표나 정답 소유자를 빌려 복원하지 않고 판단 불가로 처리한다. 팀/다른 팀원은 non-self로, 본인은 self로 구별한다. 개별 팀원 신원까지 평가하지 않는다.

C. 수치 보존: 지표 바로 뒤에서 값·단위·방향 연결자(→, ⇒, ->, 에서)가 있는 전후 관계, 또는 명시적인 개선 전/개선 후 라벨과 값의 순서가 붙어 있는 관계를 파싱한다. 지표·값 둘·단위·방향을 튜플로 비교한다. 서로 떨어진 숫자 두 개로 성공 처리하지 않는다. 증가/감소 표현이 반대로 남거나 값/단위가 잘못 연결된 완전한 관계가 있으면 잘못 연결됨. 올바른 반복 관계가 있어도 완전한 반대 관계가 함께 있으면 보수적으로 실패한다.

B/C의 사전 범주: preserved(보존), mislinked(잘못 연결됨: 명시적으로 반대 소유자/잘못된 값·단위·방향 연결), missing(누락: 핵심 작업 또는 관계 자체가 복원되지 않음), indeterminate(판단 불가: 내용 조각은 있지만 연결/주어를 확정 불가). 단순 OCR 철자 훼손으로 주요 작업 앵커가 불완전하면 누락에 포함되며 실제 시각적 검출 누락만 의미하지 않는다. 규칙 기반 보수적 채점으로 자연어 동의어를 완전히 다루지 못한다. 작업 핵심 앵커의 완전성은 부수 동사 전체의 전사 정확도와 다르다. 자동 판정을 출력 구절과 함께 감사하되 사전 규칙이나 정답을 바꾸지 않는다. 잘못 연결됨/판단 불가 모두 실제 OCR 원문 증거를 남긴다. 전부 success/total과 4범주 건수로 보고한다.

단일 실행 에이전트의 시각 검수/감사이며 독립 사람 이중 검수, 외부 LLM 채점이 아니다. 합성 결과를 실제 학생 자료, 기존 OCR 또는 Gemini 우위의 근거로 일반화하지 않는다.
