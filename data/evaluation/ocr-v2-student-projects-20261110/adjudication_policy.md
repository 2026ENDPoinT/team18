# 추론 후 수치 채점 감사 기록

이번 파일과 audit_metrics.py는 **추론 후** 작성했다. 최초 manifest/정답/이미지/규칙/예측/summary는 변경하지 않는다. 최초 고정 점수와 감사 후 점수를 모두 공개한다. 보고서의 C는 감사 후 의미 보존 점수이며 사전 등록된 파서 점수와 구별한다.

실제 저장 출력을 검토하자 최초 규칙 구현의 두 한계가 확인되었다.

1. 단위 정규식에 한글 전체를 허용한 탓에 p07 결과의 `240ms` 뒤 다음 줄 `좌석 조회 중앙값`을 단위에 흡수했다. p10 결과의 `9m` 뒤에도 같은 문제가 생겼다. 두 건의 잘못 연결됨 판정은 OCR 오류가 아닌 채점기 오류다. 단위 토큰을 영문 단위, %, 건/s로 분리하고 원문 구절에 걸쳐 단위를 확장하지 않는다.
2. 초기 파서는 화살표 또는 공백 없는 전후 라벨 쌍만 허용했다. 그러나 `예약 API p95 420ms  180ms로 감소`는 숫자 두 개만 있는 구절과 다르다. 지표, 같은 단위의 두 값, 두 번째 값에 붙은 목적지 조사 `로`, 방향 술어 `감소`가 국소적으로 연결되어 있다. 사전에 고정한 사실 (예약 API p95, 420, 180, ms, 감소)을 복원할 근거가 있으므로 의미 보존으로 판정한다. 화살표 유실은 CER에 그대로 남는다.

감사 파서는 세 가지 연결 근거만 인정한다.

- 지표 바로 뒤의 `값+단위 → 값+단위` (화살표가 LF로 나뉘어도 연속 관계라면 허용).
- 지표 바로 뒤의 `값+단위 값+단위로 증가/감소`. 숫자만 있으면 불충분하다. 두 번째 값을 도착값으로 지정한 조사와 방향이 모두 필요하다.
- 단일 지표 범위에서 `개선 전` 바로 뒤의 값/단위와 `개선 후` 바로 뒤의 값/단위가 각각 결합된 경우. 두 쌍 사이에 다른 설명이 끼어도 각각의 라벨·값이 인접해야 한다. 다른 지표명이 섞이면 허용하지 않는다. 원문 이미지의 위치나 막대 길이를 근거로 보완하지 않는다.

값/단위/방향이 반대이거나 같은 지표의 완전한 모순 관계가 함께 있으면 잘못 연결됨이다. 숫자 존재만으로 성공시키지 않는다. 모든 28개 성과 사실을 동일 규칙으로 재평가하고, 긍정/부정 사례 10개를 점검한다. A/B, CER, 처리시간, 성공/빈 출력/오류 상태는 최초 실행 그대로다. 외부 LLM은 사용하지 않는다.

추론 후 보완한 파서이므로 최초 사전 규칙 점수보다 확증 편향 위험이 있다. 따라서 최초 C=4/28과 감사 후 점수를 함께 제공하고, 모든 변경 항목·실제 OCR 증거·스크립트 해시를 저장한다. 실제 학생 자료에서는 독립 검수자가 이 의미 보존 판정을 다시 검증해야 한다.
