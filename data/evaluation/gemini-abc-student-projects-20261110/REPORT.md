# 비교 결과: 이번 36장에서는 원본 PNG 직접 입력(A)이 가장 유리했다

기존 LocalOCR를 다시 실행하지 않고 저장된 36장과 OCR 문자열을 그대로 사용했다. 모델은 `gemini-3.5-flash-lite`, 12개 합성 프로젝트의 36장 × 3조건에서 **108개 정상 응답**을 확보했다. 아래는 이 표본과 고정 프롬프트의 결과다.

| 조건 | 전사 CER, 공백 제거↓ | 구조화 기술명↑ | 구조화 역할 귀속↑ | 엄격한 성과 JSON 일치↑ | OCR 포함 시간 중앙값* |
|---|---:|---:|---:|---:|---:|
| A: 원본 PNG → Gemini | **2.12%** | 84/84 | **56/56** | 27/28 | 5.650초 |
| B: LocalOCR 텍스트 → Gemini | 13.83% | 84/84 | 48/56 | 26/28 | 5.473초 |
| C: LocalOCR 텍스트 + PNG → Gemini | 8.97% | 84/84 | **56/56** | 25/28 | 8.698초 |

*B/C의 시간은 이번 Gemini 측정에 과거 해당 페이지 LocalOCR 시간을 더한 추정값이다. 같은 파이프라인을 다시 측정한 값은 아니다. Gemini만의 중앙값은 A 5.650초, B 3.264초, C 6.667초였다. 배치 사이 호출 제한 대기는 이 중앙값에 포함하지 않는다.

기존 LocalOCR 단독의 CER은 13.83%, 역할 귀속은 40/56이었다. 이는 전사 문자열에 적용한 규칙 기반 보존 점수로, 표의 Gemini 구조화 JSON 해석 점수와 측정 대상이 다르다. 기존 LocalOCR의 16개 미확정 역할은 모두 좌우 비교 페이지에서 나왔다.

## 판단

**이 자료 유형의 기본 후보는 A다.** A는 가장 낮은 전사 CER과 완전한 역할 귀속을 보였다. B는 입력 토큰이 적고 Gemini 응답도 빨랐지만, 이미 사라진 열 구조를 안정적으로 복원하지 못했다. C는 이미지 덕분에 구조화 역할 귀속을 맞혔으나 전사에서는 OCR의 열 혼합 순서를 유지한 페이지가 많았고, 입력 토큰·OCR 포함 시간이 증가했다. 이번 실행에서는 C를 기본 경로로 삼을 추가 이점이 확인되지 않았다.

C와 A를 같은 페이지끼리 비교하면 C의 공백 제거 CER이 더 높은 페이지 17장, 같은 페이지 17장, 더 낮은 페이지 2장이다. B는 36장 모두 A보다 높았다. 이는 단일 실행 기술 통계이며 반복 실험의 유의성 검정은 아니다.

전사 품질과 문서 이해를 분리해야 한다. C의 구조화 역할은 56/56이지만 전사 문자열만으로 확인되는 역할은 42/56이었다. 이미지에서 역할을 해석하면서도 전사 출력에는 혼합된 OCR 순서를 남기는 양상이므로, 후속 단계가 JSON과 전사 중 무엇을 사용하는지에 따라 결과가 달라진다.

## B의 역할 오류는 실제 귀속 오류다

좌우 비교 슬라이드 8장의 역할 16개 중 B는 8개를 맞혔고 8개를 잘못 연결했다. **8장 모두 팀 작업을 본인 작업(self)으로 확정**했다. 불명확하면 unknown으로 두라는 공통 지시가 있었지만 이 8개는 unknown으로 남기지 않았다. 같은 페이지의 본인 작업 8개는 정답과 일치했으나, 원시 텍스트의 기존 보수적 규칙으로는 16개 모두 귀속 근거를 확인할 수 없었다. 따라서 B의 전체 48/56을 근거가 충분한 복원률로 해석해서는 안 된다.

대표 사례 `p01_slide_compare`:

- 원본 이미지 왼쪽은 **팀 전체 구현 → 예약 화면과 관리자 승인 기능**, 오른쪽은 **내가 맡은 역할 → 중복 예약 차단 API와 트랜잭션 처리**다. 이 한 장은 이번 후속 검토에서 원본 이미지를 직접 확인했다.
- LocalOCR는 두 제목을 먼저 읽고 양쪽 작업을 뒤섞었다.
- B는 `예약 화면과 관리자 승인 기능을`의 owner를 `self`로 반환했다. 인용 구절도 원시 OCR의 연속 구절이 아니었다.
- A/C는 같은 작업을 `team`으로 반환했다.

## 성과 JSON 점수의 감점은 숫자 판독 오류와 구별된다

사전에 고정한 엄격 채점은 지표명, 숫자 문자열, 두 단위, 방향이 모두 일치해야 한다. 점수를 사후 보정하지 않았다. 감점된 모든 항목을 확인한 결과는 다음과 같다.

| 조건·페이지 | 감점 원인 | 해석 |
|---|---|---|
| A / p11_intro | `검색 Recall@5`를 `Recall@5`로 축약 | 지표명 완전 일치 실패. 61→83, %, 증가는 정확 |
| B / p03_slide_bullets | after_unit=`kg로` | 단위 필드에 조사 혼입. 18.4→11.2는 정확 |
| B / p10_intro | after_unit=`m로 감소` | 단위 필드에 조사·방향 혼입. 24→9는 정확 |
| C / p11_intro | `검색 Recall@5`를 `Recall@5`로 축약 | A와 같은 지표명 불일치 |
| C / p02_slide_bullets | after_unit=`%로 증가` | 단위 필드에 조사·방향 혼입. 91→99는 정확 |
| C / p04_slide_bullets | after_unit=`%로 감소` | 단위 필드에 조사·방향 혼입. 3.2→0.8은 정확 |

모든 조건의 **전사 문자열에는 성과 관계 28/28이 보존**되었다. 따라서 표의 27/28·26/28·25/28을 숫자를 그만큼 잘못 읽었다는 뜻으로 쓰면 부정확하다. 구조화 필드의 정확성 문제이며, 엄격 채점에서 `missing`이나 `mislinked`로 분류된 이유를 위와 같이 공개한다. 별도의 의미 보정 점수는 만들지 않았다.
